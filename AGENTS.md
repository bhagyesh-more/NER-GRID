# NER-GRID Engineering & Contributor Rules (AGENTS.md)

This document establishes the mandatory engineering standards, architectural principles, and ethical constraints for all human developers and AI assistants working on **NER-GRID** (SIH 2026 Problem SIH26002).

---

## 1. Ground Truth & Data Integrity Mandate

NER-GRID is designed as a mission-critical logistics decision-support platform for the North Eastern Region of India. In real disaster and supply-chain scenarios, inaccurate or fabricated data leads to catastrophic routing and resource allocation failures.

### Non-Negotiable Rules:
1. **Prefer Real Data Over Simulated Data**: Always prioritize verified, authentic datasets from recognized authorities (IMD, NRSC, NESAC, CWC, NHAI, OSM, Copernicus) over synthetic data.
2. **Never Fabricate External API Data**: Do not hard-code mocked API responses that pretend to be from live government servers (e.g. pretending a response came from `mausam.imd.gov.in` when it was generated by an LLM).
3. **Never Represent Simulated Data as Real**: If a specific data feed is unavailable, offline, or requires physical field hardware not yet deployed, simulated fallbacks must be explicitly labeled.
4. **Data Origin Taxonomy**: Every ingested record, geospatial feature, hazard score, and road segment MUST carry explicit provenance metadata:
   - `OBSERVED`: Sensor-based, satellite telemetry, automatic weather stations (AWS), river gauge readouts.
   - `REPORTED`: Field reports, disaster authority bulletins (NDMA/SDMA), police advisories, crowd-verified road blockages.
   - `PREDICTED`: Model outputs, statistical forecasts, landslide susceptibility indices, hydrodynamic flood projections.
   - `SIMULATED`: Synthetic scenarios, stress-test inputs, or test fixtures generated for algorithm validation.
5. **Metadata Retention**: Retain original timestamps, station IDs, agency names, acquisition coordinates, and confidence bounds wherever practical.

---

## 2. Security & Credentials

1. **Zero Secret Leakage**: Never hard-code API tokens, access secrets, database passwords, or server credentials in source code or documentation.
2. **Environment Variables**: All configuration must load strictly from system environment variables or `.env` files via structured config loaders (e.g., `pydantic-settings`).
3. **No Claim of Unauthorized Access**: Never claim, imply, or simulate privileged/restricted access to classified or internal government networks. Respect all API quotas, terms of service, and public data policies.

---

## 3. Architecture & Modularity

1. **Modular Data Provider Pattern**: Implement all external data ingestion behind strict abstract interfaces (Adapters). Adding a new government or commercial data provider (e.g., swapping a fallback weather provider with an official IMD REST endpoint) must never require rewriting the core optimizer, hazard engine, or frontend.
2. **Deterministic Routing & Transparent Optimization**: Route recommendations must have explainable weights (e.g., travel time vs. landslide risk vs. flood inundation depth vs. road grade). Do not treat pathfinding as a black box.
3. **Graceful Degradation**: In the North Eastern Region, cellular connectivity and power grids frequently fail during monsoons. The system must support offline caching of elevation rasters, road graphs, and pre-calculated baseline hazards.

---

## 4. Scientific & Machine Learning Rigor

1. **No Invented Metrics**: Do not claim arbitrary accuracy, precision, F1-scores, or ROC-AUC metrics (e.g., "Our model achieves 99.4% landslide accuracy") without a reproducible evaluation notebook, real ground-truth validation data, and documented methodology.
2. **Physical Feasibility**: Terrain slopes, rainfall thresholds (e.g., Caine's empirical rainfall-intensity-duration curve), and vehicle payload limits must reflect realistic geography and vehicular constraints in mountainous terrain (e.g., NH-10, NH-29, NH-06).

---

## 5. Engineering Quality & Testing

1. **Automated Ingestion Tests**: Every data parser and transformer must have corresponding unit tests validating schema conformity, coordinate handling, edge-case nulls, and fallback behavior.
2. **Type Safety**: Use static typing everywhere (Python type hints + Pydantic v2 schemas; TypeScript strict mode for frontend).
3. **Specification Discipline**: Do not add extraneous features or change the core scope without first updating [prototype-spec.md](file:///d:/Projects/NER-GRID/prototype-spec.md).
